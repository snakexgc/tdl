# 真实账号串行验证记录

日期：2026-09-19。用户明确授权使用项目 `.tdl` 下的已登录账号，允许创建测试群，但要求保留群聊、保守控制并发。

## 账号和执行边界

- 原账号 Bolt 文件以只读方式打开，只复制 session、应用标记、凭据指纹三个键到内存。会话更新和测试任务状态均写入内存，未启动原有监听、Bot 或下载队列。
- 每次实测结束比较原账号文件的 SHA-256，确认逐字节未变；配置热更改实测也检查原 `config.json` 的 SHA-256 未变。没有重新登录、退出登录、替换会话或邀请成员。
- 复用账号的单个 Telegram 连接；上传线程、文件并发、aria2 split 和连接数均为 1。测试 RPC 串行执行，每次结束后至少间隔 1 秒；建群之间额外间隔 5 秒。收到 FLOOD_WAIT 即取消测试。
- 没有压力测试、并发测试或公网最高速度测试。记录的下载耗时包含主动限速，不代表项目吞吐能力。
- 聊天目录仅记录条目数量；没有把现有聊天内容、手机号、用户名、访问哈希或会话凭据写入测试日志或版本库。

## 实际结果

| 检查 | 结果 |
| --- | --- |
| 现有会话鉴权 | 通过，未触发登录流程 |
| 生产聊天目录适配器 | 通过，能够读出测试前后的会话列表并解析新建群 |
| 自建测试文件 | 在来源群上传一个确定性生成的 4 MiB 二进制文件；未读取现有聊天里的文件 |
| HTTP 下载 | 返回 4,194,304 字节，SHA-256 与上传前内容相同；本次主动限速下约 8.242 秒 |
| 非对齐 Range | `bytes=137-65535` 返回 206，逐字节匹配原文件对应区间 |
| RTE 本地下载组件 | 下载完成，4 MiB 文件 SHA-256 相同 |
| 真实 aria2 → 生产 HTTP → Telegram | 隔离 aria2 实例下载完成，4 MiB 文件 SHA-256 相同 |
| HTTP 配置热更新 | 公网链接地址及 TTL 原地更新；不重启监听，新的地址仍能完成 Range 请求 |
| 多规则、多目标 | 两条存在目标重叠的规则，两个目标群各收到一次官方转发 |
| 重复入队 | 同一个来源消息/目标返回已有任务，目标群没有多出消息 |
| 转发规则热更新 | 停用多目标规则后，仅目标 A 收到一次 clone 消息，目标 B 未收到该消息 |

转发实测使用测试群内自建消息，经规则端口路由、生产 RTE 队列和真实 Telegram 传输执行。没有引入第二账号制造真实入站消息，因此没有实测“他人发消息 → 更新监听 → 自动转发”的完整入口；既有自动入口单元测试仍承担这部分回归。程序忽略自己发出的自动转发消息这一保护保持不变。

实测分四次顺序运行：鉴权 1 次 RPC；下载阶段 56 次 RPC；转发阶段 25 次 RPC；HTTP 热更新阶段 8 次 RPC。没有同时运行两个真实账号测试进程。

## 可重复执行的入口

`app/watch/live_account_test.go` 默认跳过；只有显式设置 `TDL_LIVE_ACCOUNT_TEST=1` 才连接账号。`TDL_LIVE_STAGE` 可选 `transfer`、`forward`、`http-hot`，不指定则只检查现有鉴权。`TDL_LIVE_PROXY` 指定本次连接使用的代理，不改部署配置。

运行命令为 `go test ./app/watch -run '^TestLiveAccountSerialSmoke$' -count=1 -v -timeout 14m`，每次只运行一个进程。`transfer` 需要先准备仅监听本机 23969、并发为 1 的隔离 aria2（测试 RPC token 为 `tdl-live-validation`）；测试 HTTP 端口为 23950。不要把该测试指向现有 aria2 任务实例。已有 receipt 会复用群聊和文件，转发阶段会在测试群内增加新的验证消息。

普通 `go test`、竞态测试和 CI 不设置这些环境变量，不连接真实账号。真实账号测试不用于扩大并发、测试限流阈值或验证大流量吞吐。
