# 日志规范

项目统一使用现有的 `DEBUG / INFO / WARN / ERROR` 四级日志。默认记录 `INFO` 及以上；WebUI「系统设置 → 详细日志」开启后记录 `DEBUG`，保存后立即影响所有输出和已创建的子 logger。

## 分级

| 级别 | 使用场景 | 示例 |
| --- | --- | --- |
| DEBUG | 高频细节、正常跳过、主动取消、重复重试 | Range 请求与分片、表情去重与筛选、机器人长轮询临时网络错误、组件启动/停止中间状态 |
| INFO | 用户关心的已发生结果、关键状态变化 | 启动/停止、连接恢复、任务提交与开始/完成、用户控制操作、配置生效、登录成功 |
| WARN | 可以继续服务或稍后恢复的异常、拒绝与降级 | 首次连接失败、等待重试的转发、执行器拒绝后检查后续执行器、通知更新失败、组件依赖阻塞 |
| ERROR | 当前操作最终失败、任务重试耗尽、组件不可用 | 下载失败、转发最终失败、任务结果保存失败、组件诊断错误、运行初始化失败 |

正常停机和调用者取消不记录为错误。底层函数返回错误，由掌握最终结果的调用边界记录一次；底层必要的分片上下文使用 DEBUG。aria2 连续连接失败首次记录 WARN，后续尝试记录 DEBUG（附尝试次数和等待间隔），成功恢复记录 INFO。不要用全局采样丢弃任务状态变化。

HTTP Range 的单次请求完成不代表整个文件下载完成，因此请求开始、HEAD、等待槽位和流结束使用 DEBUG；最终任务状态由下载执行器记录。状态轮询仅在持久化接受了状态变化后记录，避免重复记录每次进度更新。

## 输出与查询

- `stderr`、`.tdl/log/latest.log`、`.tdl/log/events.jsonl` 使用相同的级别开关与脱敏规则。控制台便于容器采集，文本文件用于本机排查，JSONL 供 WebUI 查询与导出。
- 两类文件各自按 10 MB 轮转，最多 3 份备份、保留 7 天并压缩。内存保留最新 5000 条；重启恢复当前 JSONL，旧文本和轮转备份不自动导入。
- WebUI 可按账号、功能、组件、级别、诊断类型、时间和关键词查询。账号为空的记录属于系统公共记录。
- 日志文件或控制台写入失败时，已收到的结构化记录仍保留在内存，并在日志管理页显示对应输出端的错误。一个输出端恢复不会清除其他输出端的故障提示。
- 消息最多保留约 8 KB，详情最多 16 KB；过大的结构化详情保存为带 `truncated`、`original_bytes` 和 `preview` 的有效 JSON，避免导出出现截断 JSON。

## 字段与接入

业务日志在创建 logger 或输出时明确设置 `component`（Manifest 中的 ID），有账号上下文时设置 `account`。默认 `kind=runtime`；诊断存储写入 `kind=diagnostic`。记录保留真实的调用位置和时间；不要依赖 WebUI 根据文件名猜测新日志的组件。

优先采用稳定字段：`task_id` 是下载来源标识，`id` 是本地/执行器任务 ID，`gid` 是 aria2 ID；另有 `peer_id`、`message_id`、`executor`、`action`、`from`、`to`、`attempt`、`duration`、`error`。日志消息写事件，变量写字段，不把完整对象拼进消息。

已有 Zap 调用通过 `logctx.From(ctx)` 取得进程 logger，使用 `With` 绑定组件/账号。组件层可使用标准库 `slog`，进程启动时安装的适配器统一送入 Zap；不要为记录日志跨越组件依赖边界。新增后台异常不能只用 `fmt.Print` 或 `color` 输出。命令结果、交互提示及日志初始化前/关闭后的进程提示仍可直接输出到终端。

slog 支持嵌套分组、空属性和 `LogValuer`，保持属性所属分组与绑定时的快照。自定义 slog 等级被归入上述四级，最高归入 ERROR，不会因第三方日志等级触发进程退出。

## 敏感信息

密码、Token、API Hash、认证头、Cookie、会话数据、验证码、手机号及请求/响应正文等常见敏感字段在所有日志输出前脱敏；字符串中的常见密钥赋值、Telegram Bot Token 和代理 URL 认证信息也会处理。嵌套对象、数组、绑定字段和错误消息均经过处理，恢复的历史记录也会重新脱敏。

不得记录配置全文、登录输入、消息正文、协议原始对象和完整下载链接。Telego 的 DEBUG 原始请求/响应输出保持关闭，临时传输错误仍可在详细日志中查看。错误码、请求 ID、响应状态等诊断字段保留原值。脱敏是兜底，无法识别任意自由文本中的所有秘密，应从调用点避免记录敏感内容。

## 验证

公共日志测试覆盖动态等级、slog 标准契约、自定义等级、调用位置、嵌套与字段快照、64 位整数精度、脱敏、有效 JSON 截断、并发容量、文件恢复及输出失败。修改日志链路时运行：

```powershell
go test ./bsw/services/logging ./internal/core/util/logutil ./app/bot
go test -race ./...
golangci-lint run ./...
go run ./cmd/swc-docs
```
